# Gitea

This stack runs Gitea, PostgreSQL 15 and an Actions runner behind Traefik.
It is being replaced by the [`forgejo`](../forgejo/README.md) stack, which
describes the migration.
The external network `traefik_gateway` and certificate resolver `stepca` must
already exist. HTTP redirects to HTTPS; SSH is published on port 2222.

## Configuration

For a new installation, copy `.env.example` to `.env`, then fill in the database
password and check the paths. Keep an existing production `.env` and add only
missing settings. Restrict its permissions with `chmod 600 .env`.

Gitea and PostgreSQL use the same `GITEA__database__NAME`,
`GITEA__database__USER` and `GITEA__database__PASSWD` values. The old
`GITEA_DB_PASSWORD` and `POSTGRES_*` entries are no longer needed in `.env`.
For an existing database, retain its current credentials: changing an environment
variable does not change the PostgreSQL role password.

These are the existing production mounts:

| Variable | Host directory | Container destination |
| --- | --- | --- |
| `GITEA_DATA_DIR` | `/rpool/docker/gitea/data` | Gitea `/data` |
| `GITEA_DB_DATA_DIR` | `/rpool/docker/gitea/postgres` | PostgreSQL `/var/lib/postgresql/data` |
| `GITEA_RUNNER_DATA_DIR` | `/rpool/docker/gitea/runner` | Runner `/data` |

Keep these directories distinct. The database mount corrects the repository's
previous configuration; it matches the supplied production Compose and requires
no data move. Do not point an existing deployment at a new empty directory.
Gitea waits for PostgreSQL's readiness check before starting.

## Actions runner

The runner keeps the production name, labels, Docker socket mount and host CA
bundle. It reads its existing configuration from `/data/config.yaml` and connects
to `http://gitea:3000`. Preserve both `config.yaml` and `.runner` in its data
directory. For a new installation, prepare `config.yaml` using the configuration
generated by the chosen act_runner version before starting the runner.

An already registered runner uses `/data/.runner`; its registration token may be
left empty. A new registration needs a fresh `GITEA_RUNNER_REGISTRATION_TOKEN`
from Gitea. Do not commit tokens. Revoke any exposed registration token in Gitea;
this is separate from the credentials of an already registered runner.

The labels the runner declares come from `runner.labels` in `config.yaml`
(`ubuntu-latest`, `ubuntu-24.04` and `ubuntu-22.04` on the
`docker.gitea.com/runner-images` images). They take precedence over
`GITEA_RUNNER_LABELS`, which is only read when a runner is registered. Change
the labels in `config.yaml`.

The runner has access to the host Docker daemon. Only run trusted workflows on
this host. Moving it to a dedicated host is a separate migration.

## Validate and apply

From this directory, validate without printing the resolved secrets:

```sh
docker compose --env-file .env config --quiet
```

Before applying, back up the database and Gitea data, check the existing mounts,
and retain the production Compose project name. A different project name can
change the network identity or conflict with the existing container names.

The image references remain `gitea/gitea:latest`, `postgres:15` and
`gitea/act_runner:latest` to avoid selecting an unverified version. Record the
running image digests before pinning them in a separate change. Do not pull images
as part of this configuration correction. With the same images available locally:

```sh
docker compose up -d --pull never
docker compose ps
```

This recreates changed containers and may briefly interrupt service. Check the
web interface, SSH cloning on port 2222 and a trusted Actions job afterwards.
Compose validation alone does not verify database access, runner registration,
the private CA, or the contents of the persisted runner configuration.
